# quant_demo UI-only manual smoke checklist

Baseline: `8fe80804edec69e23f45218f58bb7d67cea15a6f`

Use the same local cache/data snapshot for baseline and candidate. Do not click a
real data update, save/delete a real record, or connect an external service while
collecting evidence.

## Route and viewport matrix

Check every route at `1440x900`, `768x1024`, and `320x568`:

- `/`
- `/timing`
- `/us_timing`
- `/hk_timing`
- `/commodity`
- `/live`

For each combination, save a named screenshot and verify:

- the shared navigation, page context, main content, forms, tables, charts, and
  dialogs remain usable;
- the page itself has no horizontal overflow;
- wide tables/charts scroll only inside their named container;
- the visible KPI values, curve first/last points, and one representative table
  row match the fixed snapshot.

## Network parity

For one normal browsing flow per route, save a DevTools HAR or a normalized table
of method, endpoint, query, and body. Compare the request multiset with the
baseline. Confirm there is no new route and no new request generated by page
navigation, the reading guide, or layout controls.

Also spot-check the existing parameter action, full holdings request,
`refreshAll()`, and update callback wiring. Do not trigger a real update.

## Copy and display corrections

- Cache-reading CTAs say “查看缓存结果” or “查询对应缓存结果”.
- A cache miss explains that the browser will not calculate online.
- Missing fixed OOS metrics say “当前缓存响应未提供 OOS 指标”.
- Rolling 1m/1q/6m windows are called “近期切片”.
- `/live` clearly says it is a manual snapshot/reconciliation page and does not
  connect to a broker or send orders.
- The sector ranking uses the API `latest_ranking` rows.
- Commodity uses `equity_curve[].value`, `metrics.calmar_ratio`, and top-level
  `win_rate` without multiplying percentage strings twice.
- HK trade history uses `trade_details` fields and does not infer P&L from
  adjacent closes.

## Keyboard and drawers

- The skip link reaches the single `<main>`.
- Desktop and mobile navigation expose the current page.
- The mobile menu and “如何阅读” drawer have accessible names.
- Opening a drawer moves focus inside it; Escape closes it; focus returns to the
  opening button.
- All new controls have visible focus and work with keyboard activation.
- The guide contains five reading steps and the short glossary.

If an axe tool is already available, a single non-blocking spot-check is useful;
do not install a runner or dependency for this task.

## Necessary interaction correctness

With a fixed local stub or DevTools request blocking (never real writes):

- rapidly activate the update, snapshot-save, and delete controls twice; each
  original handler should be entered once while pending and become usable again;
- delay two result GET responses, switch strategy/period quickly, and verify only
  the last selection updates response-derived state and the visible result;
- confirm all GET requests still leave the browser and no request is aborted;
- confirm `ui_shell.js` performs no network, update-flow, reload, or form action.

## Frozen boundaries

Before review, compare against the baseline:

- changed paths are limited to approved templates, `static/css/ui.css`,
  `static/js/ui_shell.js`, and this checklist/optional fixtures;
- `web/blueprints/**`, `web/state.py`, `web/serializers.py`, `web/params.py`,
  `engine/**`, `strategies/**`, `timing/**`, `services/**`, data/cache/build/deploy
  files, `web/blueprints/pages.py`, and `static/js/data_update_flow.js` have zero
  diff;
- all six original URLs return HTTP 200 and existing tests pass.
